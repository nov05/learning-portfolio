# 🟢 **Compare-And-Swap (CAS)**

Gemini:  

**CAS（Compare-And-Swap，比较并交换）** 是一种在并发与分布式系统中广泛使用的**原子操作（Atomic Operation）**，用于在无锁（Lock-free）状态下安全地更新数据。

它包含三个核心参数：`CAS(内存地址, 预期旧值, 新值)`。

**核心工作机制**

1. 系统检查“内存地址”当前存储的实际值是否等于“预期旧值”。
2. **如果相等**：说明数据在此期间未被其他线程/节点修改，系统会将该地址的值更新为“新值”，操作成功并返回 `true`。
3. **如果不相等**：说明数据已被其他人抢先修改，操作放弃更新，直接返回 `false`。

上述整个“检查并替换”的过程是不可分割（原子化）的，不会被中途打断。

**在分布式与并发上下文中的作用**
在您引用的这段话中，CAS 被用来实现 **Fetch-and-Add（读取并加一）** 逻辑（通常称为 **CAS 自旋重试环/CAS Loop**）：

* **操作步骤**：节点先读取当前值 $V$，计算出新值 $V+1$，然后执行 `CAS(地址, V, V+1)`。
* **处理冲突**：如果在这期间有其他节点改动了数据导致 CAS 失败，该节点就会循环重试（Retry），重新读取最新值并再次尝试 CAS，直到成功。

**共识等级与理论意义**
在分布式系统与多处理器理论中（如 Herlihy 的无锁同步层级）：

* CAS 具有**无限共识数（Infinite Consensus Number）**。这意味着仅靠 CAS 这一原语，就可以在任意数量的节点/线程之间解决共识问题（Consensus Problem），并实现任意无锁数据结构。
* 正因如此，文本中提到“由于你可以用共识（Consensus）实现 CAS，你也可以用共识实现 Fetch-and-Add”。
